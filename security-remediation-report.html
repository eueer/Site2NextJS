2. Detailed Code Remediation & Implementation Evidence (Part 1)

SEC-01: CLI Arbitrary File Write & Zip Slip Traversal Prevention Fixed
src/cli.ts • Lines 44–68

Vulnerability: When running npx framer2nextjs, crawled file paths were joined with path.join(targetDir, f.path) without boundary checks, enabling malicious crawled sites to write outside the output folder.

Remediation: Confined every file path to targetDir using path.resolve, blocked relative directory stepping (..), and explicitly prevented writing to CI/git metadata directories.

// src/cli.ts - Lines 44-68 (Boundary Confinement) + for (const f of report.files) { + if (!f.path || f.path.startsWith("/") || f.path.startsWith("\\")) continue; + const normalized = path.normalize(f.path); + if (normalized.startsWith("..") || normalized.includes(`..${path.sep}`)) continue; + if (normalized.startsWith(".github") || normalized.startsWith(".git")) continue; // Block CI hijack + const fullPath = path.resolve(targetDir, f.path); + if (!fullPath.startsWith(targetDir + path.sep)) continue; // Zip slip guard + fs.mkdirSync(path.dirname(fullPath), { recursive: true }); + fs.writeFileSync(fullPath, f.content ?? f.binary); + }
SEC-02: GitHub Push Route Workflow Injection & Payload Defense Fixed
src/app/api/github/push/route.ts • Lines 39–135

Vulnerability: The GitHub push API accepted arbitrary incomingFiles. An attacker could craft a payload with path: ".github/workflows/deploy.yml" containing malicious shell commands, resulting in remote code execution in the user's repository via GitHub Actions.

Remediation: Added 15MB request payload limit, capped maximum files at 500, and strictly rejected any files targeting .github/, .git/, or .env.

SEC-03: Rate Limiter Header Spoofing Defeat (Anti-Spoofing IP Resolution) Fixed
src/lib/rateLimit.ts • Lines 93–145

Vulnerability: getClientIp previously read the first entry of x-forwarded-for. Attackers could bypass rate limits indefinitely by rotating spoofed client-controlled IP strings in the header.

Remediation: Prioritized tamper-proof edge headers (x-vercel-forwarded-for, cf-connecting-ip, req.ip, x-real-ip) and switched x-forwarded-for to read the rightmost IP (closest to the trusted reverse proxy) with strict syntax validation.

SEC-04: SSRF Cloud Metadata & Internal TLD Protection Fixed

3. Detailed Code Remediation & Implementation Evidence (Part 2)

SEC-05: SVG Stored Cross-Site Scripting (XSS) Mitigation Fixed
src/app/assets/[...path]/route.ts • Lines 35–48, 75–80, 130–135

Vulnerability: Crawled .svg assets were served with Content-Type: image/svg+xml without CSP headers. Malicious SVGs containing embedded <script> tags could execute JavaScript in the context of the application's domain.

Remediation: Created createAssetHeaders() to inject a strict Content-Security-Policy that disables all script execution and plugin instantiation inside SVGs.

// src/app/assets/[...path]/route.ts - Lines 35-48 (SVG CSP Sandbox) + function createAssetHeaders(contentType: string): Record { + const headers: Record = { "Content-Type": contentType, "X-Content-Type-Options": "nosniff" }; + if (contentType.includes("image/svg+xml")) { + headers["Content-Security-Policy"] = "default-src 'none'; style-src 'unsafe-inline'"; + headers["Content-Disposition"] = "inline"; + } + return headers; + }
